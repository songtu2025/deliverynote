# 导出 Excel 格式可编辑设计

## 背景

系统当前通过同一个 `write_delivery_workbook` 流程生成 Web 单文件导出、批次 ZIP 内文件和 CLI 输出。生成文件包含“交货导入”和“待处理导入”两个工作表。工作表保护用于锁定前两行和 A:G 正式导入表头，第三行起的数据单元格保持可编辑。

用户希望下载文件后，能在 Excel 或 WPS 中自行调整列宽、行高、字体、颜色、边框、对齐和自动换行，同时不能误改正式导入表头或字段顺序。

## 目标

- 保持工作表保护开启。
- 保持第 1、2 行及正式导入表头内容锁定。
- 允许用户格式化单元格、行和列。
- 保持第 3 行起的数据单元格可编辑。
- 保持现有 A:G 字段、字段顺序、模板初始样式、文件命名和业务数据不变。
- Web 导出、批次 ZIP 内文件和 CLI 输出行为一致。

## 非目标

- 不在网页中增加列宽、行高或样式配置界面。
- 不保存用户在本地 Excel/WPS 中做出的格式修改。
- 不解除工作表保护。
- 不允许通过系统生成过程改变正式导入表头名称或列顺序。
- 不修改采购匹配、数量守恒、拆分、导出数据或 ERP 回写行为。

## 方案选择

采用“保留工作表保护，只开放格式编辑”。未选择以下方案：

- 完全解除保护：会允许误改表头和字段结构，存在 ERP 导入失败风险。
- 同时生成保护版和自由编辑版：会增加文件数量和操作成本，超出当前需求。

## 详细设计

### 保护规则

在现有表头保护函数中显式配置工作表保护权限：

- `sheet = True`：继续启用工作表保护。
- `formatCells = False`：允许修改字体、字号、颜色、填充、边框、对齐和自动换行等单元格格式。
- `formatColumns = False`：允许调整列宽及列格式。
- `formatRows = False`：允许调整行高及行格式。
- `selectLockedCells = False`：允许选中锁定的表头单元格以修改其格式。
- 第 1、2 行单元格继续设置 `locked = True`，因此只能调整格式，不能修改内容。
- 第 3 行起继续设置 `locked = False`，保持现有数据编辑能力。

OpenPyXL 的工作表保护属性表示“是否禁止该操作”，因此上述三个格式属性使用 `False` 表示允许用户操作。

### 影响范围

修改只位于共享的 Excel 写出逻辑，不增加 API、数据库字段或前端状态。由于 Web Worker 和 CLI 都调用 `write_delivery_workbook`，以下输出自动保持一致：

- Web 单个来源文件下载。
- 批次 ZIP 中的每个来源文件。
- CLI 生成的交货处理文件。

“交货导入”和“待处理导入”两个工作表使用同一规则。上传模板提供的初始列宽、行高和样式仍会被继承；本功能只决定用户下载后是否能够继续调整。

### 数据流与错误处理

业务数据生成、模板复制、数据填充和文件保存流程保持不变，只在保存前设置保护权限。该设置不新增运行时输入，也不新增独立失败分支。模板字段校验、文件写入错误和原有导出任务错误仍沿用现有处理逻辑。

## 兼容性

- A:G 正式导入表头及顺序不变。
- 模板第 3 行样式复制规则不变。
- “待处理导入”辅助列和现有默认宽度、行高不变。
- 原有 CLI 参数、输出目录和文件命名不变。
- Excel/WPS 用户可以调整显示格式，但不能修改锁定表头内容。

## 测试设计

扩展现有 Excel 导出测试，重新打开生成的工作簿并验证两个工作表：

1. 工作表保护仍开启。
2. `formatCells`、`formatColumns`、`formatRows` 均为 `False`。
3. `selectLockedCells` 为 `False`。
4. 第 1、2 行单元格仍为锁定状态。
5. 第 3 行数据单元格仍为未锁定状态。
6. 表头内容、A:G 字段顺序、模板样式和业务数据保持不变。

随后运行全部 Python 测试和 `pip check`。本变更不修改前端，但仍需确认既有生产构建不受共享交付分支其他改动影响；部署前按照项目规则完成 Compose 配置检查和导出业务冒烟验收。

## 验收标准

- 用户打开新生成的 Excel/WPS 文件后，可以调整列宽、行高及单元格格式。
- 用户不能修改第 1、2 行和正式导入表头内容。
- 用户仍能编辑第 3 行起的数据内容。
- Web、批次 ZIP 和 CLI 输出规则一致。
- 原有导出格式、命名和业务结果无回归。
