# SEEKWAY Web 界面开发标准

- 规范基线：SEEKWAY V2.1.0，按 DeliveryNote 适配。
- 适用范围：DeliveryNote 内部供应链 PC 系统。
- 视觉基线：项目现有主题、组件和页面；公司设计系统作为补充参考。
- 维护责任：DeliveryNote 项目维护者。
- 接入日期：2026-10-29；来源与项目差异见 [README](../README.md#codex-规范接入)。

本文件保存界面通用规则并索引专项规范。现有项目保留已验证的设计系统，在“项目配置”中记录差异，不为套用默认值重构。

新建、明显重设计或方向不明确的界面按 `docs/codex/interface-design.md` 执行。采用与现有规范不同的方案前，须确认并更新下方“项目配置”，不得静默更换已确认的设计系统。

## 1. 项目配置

以下配置记录当前实现和后续验收目标，不表示已完成全站视觉或可访问性验收。

- 公司品牌名称：`SEEKWAY`；产品名称为 `DeliveryNote`，沿用现有展示。
- 项目主色：`#055247`，对应现有根级 Token 与 `--dn-primary`。
- 色彩体系：雾蓝。中性底 `#f1f4f8`，正文 `#182230`，次要文字 `#667085`，控件边框 `#848ea0`，分隔线 `#e3e8ef`；语义色：需要人处理 `#b4381f`、失败 `#a3162b`、进行中 `#2d5c94`、完成 `#1f6b52`。珊瑚只表示需要人处理，失败另加感叹号图标。
- UI 组件库：React 19、Ant Design 6；版本以项目清单与锁文件为准。
- 图标体系：`@ant-design/icons` 6，保持单一主要业务图标体系。
- 图表库：当前未引入；有确认的需求时再评估和审批依赖。
- 默认语言：简体中文。
- 默认时区：Web 使用 `Asia/Shanghai`，数据库和后台任务使用 UTC。
- 主要设计视口：`1440 × 900`；相关界面任务按布局规范验证。
- 最小验收视口：`1024 × 640`，当前全站覆盖情况尚未统一验证。
- 移动端范围：面向 PC，保留已有窄屏适配；不自行扩展移动端业务流程。
- 公司设计系统：[SEEKWAY Web UI Kit V1.2.0](https://www.figma.com/design/eed9GukOv7zM7n04Lu1xUl)。
- 项目主题入口：[App.tsx](../frontend/src/App.tsx) 的 `ConfigProvider` 与 `App` 上下文。
- CSS 语义变量：[base.css](../frontend/src/styles/base.css) 的 `--dn-*`；样式由 [styles.css](../frontend/src/styles.css) 引入。
- 允许的项目差异：沿用现有浅色侧栏、布局、页面密度、字体、主色及 `36px` 默认控件高度、`6px` 基础圆角；以现有 Token 和相关页面配置为准。
- 存量问题：内部类名及 `!important` 覆盖、重复主题值按关联任务逐步治理；组件中文环境、对比度和多视口完成情况按实际验证报告，不作为已达标声明。

## 2. 规则优先级

发生冲突时按以下顺序执行：

1. 用户明确提供的设计稿和验收标准。
2. 本项目界面规范与上方已确认的项目配置。
3. 项目已有设计令牌、基础组件和相似页面。
4. 本标准的默认规则。

设计稿不得覆盖业务、权限、安全和可访问性要求。规则冲突时，必须说明并等待确认。

## 3. 专项规范路由

所有 Web 界面任务先读取本文件，再按任务内容读取下表中的专项规范。任务同时命中多项时全部读取；未命中时不加载。文件缺失时报告缺失，不假设项目外模板可用。

| 任务内容 | 必须读取 |
| --- | --- |
| 页面骨架、响应式、应用壳层、登录页、导航或页面标题 | [布局与导航](web-ui-layout-standard.md) |
| 按钮、表单、弹窗、抽屉、操作反馈或提交状态 | [表单与反馈](web-ui-form-standard.md) |
| 表格、列表、数据状态、数据格式、图标、图片或图表 | [数据展示](web-ui-data-standard.md) |

## 4. 设计原则

1. **操作高效**：减少查找、录入、比较和批量处理的步骤。
2. **保持一致**：相同概念使用相同名称、位置、组件和交互，不为单个页面另设规则。
3. **层级清晰**：一个页面只有一个主要标题，一个操作区域最多只有一个主按钮。
4. **密度适中**：默认使用中等信息密度；高频数据页面可更紧凑，但不能影响阅读和操作。
5. **状态完整**：覆盖正常、等待、无数据、失败、禁用和操作反馈。
6. **减少装饰**：普通后台功能不使用大面积渐变、装饰性插画、玻璃拟态、大标题或大留白。

## 5. 设计令牌

复用项目现有 Ant Design Token、`--dn-*` 语义变量和页面样式，不复制公司主题模板或建立第二套主题。新增或修改样式优先使用公开组件 Token、`classNames`、`styles` 或已有业务类名；不得扩展内部 DOM 覆盖。已有重复值在相关任务中逐步收敛，不新增副本。

通用交互使用 Ant Design 组件。自定义 React 区域可通过 `theme.useToken()` 读取主题值；可复用的 CSS 值集中维护。保留根级 `ConfigProvider` 和 `App` 上下文，在相关任务中验证组件中文环境。日期组件需要 Day.js 本地化时同时核对直接依赖，不自行新增依赖。

### 5.1 颜色

- 颜色按用途命名，不用 `blue-500` 等视觉名称表达业务用途。
- 侧栏及页面背景沿用现有浅色体系和语义变量，不为套用公司示例添加渐变或深色侧栏。
- 悬停、选中和焦点沿用现有主题中的等价 Token，不在业务组件重复硬编码。
- 状态颜色必须配合文字、图标或形状，不得只用颜色区分成功、警告和失败。
- 警告图形使用 `colorWarning`，小号警告文字使用 `colorWarningText`；现有主题使用等价令牌。
- 正文和占位文字与背景对比度不低于 `4.5:1`；大号文字以及承载控件边界、状态或含义的图标、边框和焦点指示不低于 `3:1`。
- `colorBorderSecondary` 或等价令牌只用于无语义的分隔线；输入框等控件边界使用 `colorBorder` 或对比度更高的组件 Token。
- 禁用状态不能只降低透明度到无法辨认，仍须保留内容可读性。

### 5.2 字体

- 优先复用当前页面字阶；新页面没有适用模式时，参考 `28px` 页面标题、`18px` 或 `20px` 分区标题和 `14px` 正文，确认后实施。
- 正文、输入内容和主要操作文字不得小于 `12px`；输入内容默认使用 `14px`，不得照搬参考项目中的 `10px` 小字号。
- 未提供 Inter 或 Noto Sans SC 字体文件时使用系统回退字体，不得自行增加远程字体或生产依赖。
- 正文默认使用常规字重，标题和需要强调的信息使用中等或半粗字重。
- 表格数字使用等宽数字特性；长编号、哈希和代码可使用项目批准的等宽字体。
- 不得仅靠字号表达层级，还应结合间距、字重和位置。

### 5.3 间距、尺寸和圆角

- 新增布局优先复用现有间距和样式；新增可复用间距按 `4px` 网格集中维护，局部调整不全量改写历史值。
- 同一表单、筛选区或操作区中的控件高度必须一致。
- 本项目默认控件高度沿用 `36px`，同类区域保持一致；密度或操作场景需要其他尺寸时按现有组件配置与已确认设计实施。
- 圆角用于表达组件边界，普通按钮、标签和输入框不使用胶囊形状。
- 表格密度按 [数据展示规范](web-ui-data-standard.md) 执行；复杂记录不得机械压缩成不可阅读的单行。

### 5.4 阴影、层级和动效

- 默认通过背景和边框区分层级，阴影只用于浮层、弹窗、抽屉和悬浮控件。
- 轻量浮层使用 `boxShadow`，弹窗和大型浮层使用 `boxShadowSecondary`；现有主题使用等价令牌。
- 层级由项目的 `z-index` 令牌管理，业务组件不得使用任意超大数值。
- 普通过渡时长使用 `120–200ms`，弹窗和抽屉使用 `200–300ms`。
- 动效不得阻塞操作或为纯装饰循环播放；必须支持 `prefers-reduced-motion`。

## 6. 可访问性

新增或修改界面按 WCAG 2.2 AA 的相关要求验证；全站历史情况未统一验收，不宣称默认达标：

- 优先使用原生 `button`、`a`、`input`、`table` 等语义元素，不能用 `div` 模拟可交互控件。
- 所有关键功能可仅使用键盘完成，焦点顺序与视觉顺序一致，焦点样式清晰且不被遮挡。
- 表单标签、错误信息、图标按钮和动态反馈必须具有可访问名称或关联关系。
- 自定义菜单、标签页、树、对话框和组合框必须遵循对应的 WAI-ARIA Authoring Practices 键盘模型。
- 目标区域至少满足 WCAG 2.2 的 `24 × 24 CSS px` 要求；SEEKWAY 后台控件默认不小于 `34px` 高。
- 不得仅依赖颜色、位置、形状、声音或悬停表达关键信息。
- 页面缩放到 `200%` 后仍可阅读和操作，文本不得被截断到无法理解。

### 6.1 界面文案

所有界面默认使用简体中文，同一业务对象只能有一个正式名称。文案应简短、直接，不使用娱乐化表达。

默认不添加解释性 Tips，按以下规则执行：

1. **禁止自行添加**：功能介绍、字段释义、业务规则复述、开发说明，以及表头或按钮已经表达的信息。
2. **保留必要文案**：字段名称、真实状态、校验错误、操作结果、确认前必须知道的影响。
3. **不换形式添加**：不把多余说明改成 Tooltip、帮助图标或折叠内容。
4. **交付前逐条检查**：新增文案删掉后，是否影响当前操作或结果判断？不影响就删除；拿不准就先省略。

- 统一名词：待处理、审校、结果，不再用“异常”“人工数量”“处理异常”“人工审校”“导出文件”“处理结果”“结果文件”作为对应界面名称。
- 数字在前、数字与单位间空一格，不用“·”连接信息。
