# SEEKWAY Web 布局与导航规范

本文件按 SEEKWAY V2.1.0 适配 DeliveryNote；来源与项目差异见 [README](../README.md#codex-规范接入)。

本文件是 `docs/web-ui-standard.md` 的专项扩展。任务涉及页面骨架、响应式、应用壳层、登录页、导航或页面标题时必须读取。

以下骨架、导航位置和密度是后台基准，不自动成为新产品探索的硬约束。结构探索按 `docs/codex/interface-design.md` 执行，确认后在项目规范中记录差异；局部任务仍沿用已确认布局。键盘、可发现性、响应式和关键操作可达性要求始终生效。

## 1. 页面骨架

采用后台基准的列表和表单页面按以下顺序组织：

```text
全局导航
└── 页面主体
    ├── 面包屑（需要表达层级时）
    ├── 页头：标题、主操作
    ├── 筛选或查询区
    ├── 批量操作和辅助操作
    ├── 数据或表单内容区
    └── 分页、结果说明或提交操作
```

Figma 的 `04 Page Templates` 只提供骨架和组件组合参考，不是运行时依赖，也不要求整页复制。现有项目继续使用原布局。

- 页面主体沿用 [app-layout.css](../frontend/src/styles/app-layout.css) 与页面已有布局；通用桌面内容区当前使用 `36px` 内边距，紧凑页面按原配置复用。响应式调整集中在相关样式模块，不新增第二套布局变量。
- 页面一级区块间距默认 `16px`；只有需要明确分组时使用 `24px`。
- 一个页面只保留一个主标题；面包屑只用于真实层级，不重复展示首页入口。
- 页面宽度沿用现有布局与相似页面，数据密集、长流程和窄表单按实际任务选择可复用模式；不引用本项目不存在的布局 Token。
- 只在内容具有独立边界、背景或操作范围时使用卡片。

## 2. 响应式

- 默认以 `1440 × 900` 设计；必须检查 `1024 × 640`、`1280 × 720`、`1440 × 900`、`1920 × 1080`，以及浏览器 `125%` 和 `150%` 缩放，关键操作均须可完成。
- 沿用现有侧栏及窄屏断点；相关修改须验证导航、当前项和焦点仍可识别，图标保留可访问名称和必要提示。不得因套用公司默认值改变当前断点和侧栏宽度。
- 最小视口允许内容区纵向滚动，但主操作不得消失，页面不得出现横向滚动。
- 数据表格确需横向滚动时，滚动只能发生在表格容器内；关键标识列和操作列应按需要固定。
- 表单在空间不足时从双列变为单列，标签和控件不得相互覆盖。
- 项目主要面向 PC，保留已有窄屏适配；没有确认的需求时不扩展移动端业务流程，窗口缩放不得遮挡内容或隐藏关键操作。

## 3. 应用壳层与登录页

- 桌面端沿用现有浅色侧栏和 `72px` 顶栏及其响应式变体；侧栏承载既有品牌和导航，不因接入规范重设计应用壳层。
- 顶部栏保留现有全局信息和用户入口；不为套用示例新增搜索、容量或任务状态功能，不放页面级筛选条件。
- 当前导航使用主色浅底、左侧强调线或等价方式高亮；任意时刻只能有一个一级导航处于当前状态。
- 登录页沿用项目已有实现和认证逻辑；业务页面不照搬登录页的大标题或品牌背景。
- 本次未接入公司登录模板。未来确需替换时先明确视觉范围、认证兼容与验收方式，获得确认后再实施。
- 沿用现有 `SEEKWAY` 品牌与 `DeliveryNote` 产品命名，修改展示前确认，不自行增加品牌后缀。

## 4. 导航与页面标题

- 导航名称使用稳定的业务名词，不使用临时活动文案。
- 同级导航按业务频率或流程排序，不按开发模块随意排序。
- 当前导航项、展开项和焦点项必须可区分。
- 页面标题描述当前对象或任务，例如“订单管理”“编辑供应商”，不用“欢迎使用”。
- 返回操作必须回到用户可预期的位置，并尽量保留列表的筛选、分页和滚动状态。
