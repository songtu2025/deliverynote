# SEEKWAY Web 表单与反馈规范

本文件按 SEEKWAY V2.1.0 适配 DeliveryNote；来源与项目差异见 [README](../README.md#codex-规范接入)。

本文件是 `docs/web-ui-standard.md` 的专项扩展。任务涉及按钮、表单、弹窗、抽屉、操作反馈或提交状态时必须读取。

## 1. 按钮与操作

- 一个操作区域最多一个主按钮，用于当前最重要且安全的下一步。
- 普通次要操作使用默认按钮或文字按钮；危险操作使用明确的危险样式。
- 按钮文案使用“动词 + 对象”，例如“新建订单”“保存配置”，避免只有“确定”“处理”。
- 同一组按钮顺序保持一致；项目组件库已有顺序时遵循组件库。
- 提交期间显示处理中状态并阻止重复提交，完成后给出明确成功或失败反馈。
- 图标按钮必须有可访问名称和提示。
- 低频操作超过三个时收纳到“更多”菜单；高风险操作不得与高频主操作紧邻且样式相同。

## 2. 表单

- 每个控件必须有持久可见的标签，占位文本不能替代标签。
- 常规表单默认标签在控件上方；短且稳定的字段可使用统一宽度的左侧标签。
- 必填标识、帮助信息和错误信息的位置在整个项目中保持一致。
- 在用户离开字段或提交时校验；错误信息必须说明问题和修复方式，并与字段关联。
- 保留已输入的有效内容，不因单个字段错误清空表单。
- 选项较少且需要对比时使用单选；选项较多时使用选择器并支持搜索。
- 开关只用于立即生效的二元状态；需要保存后生效时使用复选框或明确的表单提交。
- 日期、金额、百分比等字段在标签或后缀中明确格式和单位。
- 保存、取消等操作的位置应稳定；长表单可使用吸底操作栏，但不得遮挡内容。

## 3. 反馈、弹窗与异常

- 立即完成的轻量结果使用消息提示；需要处理的异常保留在相关区域。
- 错误信息不得暴露堆栈、数据库信息或内部错误码，可以提供脱敏追踪编号。
- 弹窗只用于需要打断当前流程的确认或短任务；复杂编辑使用独立页面或抽屉。
- 弹窗打开后焦点进入弹窗，关闭后返回触发元素，并支持键盘关闭；危险确认应防止误触。
- 删除、覆盖、停用等操作必须说明对象、影响范围和是否可恢复，按钮文案应写明具体动作。
- 全页失败提供原因说明和重试路径；局部失败只影响对应区域，不应清空其他成功内容。

## 4. 提交状态与文案

每个提交操作至少包含默认、校验失败、提交中、提交成功和提交失败。审核中、部分成功、冲突或离线等状态只在业务需要时增加。

- 确认和错误文案应引用具体对象，不能只有“操作失败，请重试”。
